# 安全策略

本仓库的安全负责人是 `@treehey`。在课程协作周期内，生产环境、部署权限、仓库规则、环境密钥和证书材料统一由负责人维护。

## 支持的分支

当前受保护并持续维护的分支：

- `server`：日常开发与联调主线
- `main`：发布、演示和最终交付主线

其他短期功能分支不视为安全支持分支，不应直接承载真实密钥或生产配置。

## 漏洞上报

发现以下问题时，不要公开提 issue 或直接开 PR 讨论细节：

- 密钥、令牌、证书、数据库连接串泄露
- 鉴权绕过、越权访问、后台接口暴露
- 任意文件读取、注入、远程执行、供应链风险
- GitHub Actions、部署链路、环境变量暴露

请私下联系 `@treehey`，并附上：

1. 问题位置
2. 复现步骤
3. 风险等级判断
4. 是否已经造成泄露

## 密钥与证书规则

- 仓库中只允许提交示例配置，例如 `.env.example`
- 真实 `.env`、`.key`、`.pem`、部署口令、云服务令牌不得提交到 Git 历史
- 生产密钥只存放在 GitHub `Environments` / `Secrets` 或负责人本地安全存储中
- 生产部署证书不得随仓库协作流转，不得通过群聊直接发送
- 如果怀疑密钥曾进入 Git 历史，按“已泄露”处理，立即轮换

## 权限原则

- `treehey` 保留唯一 Owner / Admin 控制权
- 其他成员只授予完成本组开发所需的最小权限
- 生产部署、环境变量编辑、保护分支规则修改、Secrets 修改只由 `treehey` 执行
- 任何绕过 PR、绕过评审、绕过受保护分支的行为均视为违规

## 事件响应

当出现疑似泄露或高危漏洞时，按以下顺序处理：

1. 立即冻结相关部署入口和高风险凭据
2. 轮换 GitHub Secrets、数据库口令、JWT 密钥、邮件密钥和证书材料
3. 检查最近提交、PR、Actions 日志和部署记录
4. 修补漏洞后，通过新 PR 合入 `server`
5. 由负责人确认后再发布到 `main`

详细基线可参考 [design_docs/SECURITY_AUDIT.md](design_docs/SECURITY_AUDIT.md) 和 [backend/docs/SECURITY_BASELINE.md](backend/docs/SECURITY_BASELINE.md)。
