# 信用分机制说明（当前已落地）

## 1. 基本定义

- 信用分范围：`0 ~ 100`
- 初始分：`100`
- 扣分等级：`L1/L2/L3` 对应 `-1/-3/-5`
- 评分方式：举报审核通过时，由管理员手动选择等级

## 2. 扣分触发

触发场景：
- 用户举报（`/admin/reports/:id`）审核通过
- 论坛举报（`/admin/forum/reports/:id`）审核通过

规则：
- 审核通过必须选择 `1/3/5` 分之一
- 审核驳回不扣分
- 每次扣分都会写入 `credit_score_logs`

## 3. 举报与内容处置联动

- 举报通过后：
  - 目标为帖子：帖子下线（软删除）
  - 目标为评论：按删除逻辑处理，并展示 `该评论已因违规被删除`
- 同一帖子/评论只能“通过举报”一次
- 若已有通过记录：
  - 后续同内容举报不进入管理工单
  - 同内容 `pending` 举报会被清理

## 4. 信用分阈值与限制

- `<= 90`：匹配受限
  - 用户会被置为 `isParticipating=false`
  - 不可自行恢复匹配（需先恢复分数到 `>90`）
- `<= 85`：禁止论坛发帖与评论（后端硬拦截）

## 5. 恢复机制

- 冷却期：
  - `L1`：7 天
  - `L2`：7 天
  - `L3`：14 天
- 冷却结束后：每 `2` 天恢复 `+1` 分
- 上限：最多恢复到 `100`
- 若出现新的举报通过：冷却期重新开始
- 注意：恢复分数不会自动恢复匹配参与，仍需用户手动开启

## 6. 匹配优先级（关键）

信用分是匹配资格的高优先级条件：
- 即使跨周，只要信用分 `<=90`，也不会自动恢复参与
- 匹配任务仅纳入 `creditScore > 90` 的参与用户

## 7. 用户侧展示

论坛信用分卡片支持三种状态文案：
- `还有 X 天开始恢复信用分`
- `信用分恢复中`
- `你好，满分用户`

Dashboard / Settings 在低分时会提示“信用分未达标”，并禁用恢复匹配相关按钮。

## 8. 管理端操作要点

- 管理员处理举报时，审核通过必须选定 `L1/L2/L3`
- 扣分后会返回是否扣分成功与扣分后分数
- 管理端可查看论坛信用用户及被举报历史，用于治理追踪
