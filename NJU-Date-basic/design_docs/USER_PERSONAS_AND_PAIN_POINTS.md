# NJU Match 用户群体与痛点分析

> **文档目的**：在产品差异化决策前，建立对"南大学生在 2026 年使用 / 不使用校园匹配平台"这件事的真实人群画像、痛点结构与需求层次，作为后续功能优先级决策、问卷设计、宣传文案、答辩演讲的统一底稿。
>
> **适用边界**：本文为 **二手调研综合**——综合行业报道、竞品公开数据、用户公开讨论（知乎、人人都是产品经理、澎湃、界面新闻、虎嗅、上观时评）、以及本项目已有 [PRODUCT_OPTIMIZATION_PLAN_USER_PERSPECTIVE.md](PRODUCT_OPTIMIZATION_PLAN_USER_PERSPECTIVE.md) 中的内部观察。**不替代** [P1/P1-需求分析.md](P1/P1-需求分析.md) 要求的 ≥20 份问卷 + ≥4 人访谈的一手调研。一手调研落地后应回填本文档（见第 9 节）。

**关键数据锚点**（后续讨论的事实底座）：

- SJTU Date 首轮匹配（2026.03.17）：女生成功率 **69.2%**，男生成功率 **39.4%**——男女配对率断层达 30 个百分点
- 一周 CP 历年活动：满意率仅 **16.28%**，活动后失联率 **53.49%**

- NJU 三校区分布：仙林（本科主体）、鼓楼（部分研究生与院系）、苏州校区（新设）——校区间通勤是产品场景设计的硬约束

**产品形态边界**：本文讨论的全部对标产品（CampusDate / SJTU Date / FDU Date / NJU Match 等）**均为网站（H5）**，不是原生 App；**Flip（去见一面）** 是微信小程序形态的同类竞品，已在武汉大学上线。**网站 + 小程序生态有完全不同于 App 的用户行为模型**，详见 §2.5。本文档所有 Persona 行为描述与产品建议均以"网站为主形态"为前提。

## 2. 宏观背景：2026 年校园关系市场的 6 个结构性趋势

### 趋势 1：从"找对象"到"探索关系"
研究生扩招后，校园社交需求从"以脱单为目的"转向"以广义关系建立为目的"。学伴、搭子、深聊朋友等弱承诺关系需求**已超过**强承诺恋爱需求。但产品端仍以"恋爱"为默认前门，错配严重。

### 趋势 2：算法疲劳
经过 Tinder / Soul / 探探 / SJTU Date 等多轮教育，年轻用户对"算法神奇匹配"已祛魅。"系统派单 vs 父母严选"的媒体辩论本质是算法权威感的衰退。**继续以"算法精度"作为唯一卖点的差异化空间正在收窄**。

### 趋势 3：身份焦虑加剧但反学历内卷情绪并行
学历内卷使"学校 / 院系 / 绩点 / 实习"成为相亲货币（QsMatch 即此范式），但学生群体内部对此的反感同样在上升——QsMatch 在知乎上骂声远多于赞声。**产品需要在"身份背书"和"反学历内卷"之间走平衡线**。

### 趋势 4：隐私恐惧上升
聊天记录截图、人脸识别误用、社工库泄露事件持续发酵。校园场景内"熟人撞见 / 被同学发现"是高敏感话题。**所有可见性默认值应从"公开"转向"渐进解锁"**。

### 趋势 5：仪式感经济
周更揭晓、节日卡片、年度报告（Spotify Wrapped 范式）成为留存抓手。"信封"、"锦书"、"占卜"等隐喻性叙事元素的产品价值正在上升。**这是 NJU Match 的现有优势区**，应巩固。

### 趋势 6：性别比失衡 = 全行业共识但无解
所有校园匹配平台都遭遇女生池小于男生池。SJTU 的 39%/69% 是公开样本，一周 CP 在男女不均的院系直接做不起来。**没有产品在结构上解决这个问题**——这是真正的开放空间。

## 2.5 产品形态约束：网站 + 小程序生态的特殊性（不是 App）

这一节是后续所有产品决策的**前提性约束**——网站 / H5 / 小程序的用户行为模型与 App 截然不同，照搬 App 范式会犯致命错误。

### 2.5.1 形态定位

| 产品 | 形态 | 入口方式 | 当前校园 |
|---|---|---|---|
| **NJU Match** | 网站（H5，njumatch.com） | 浏览器访问 / 二维码扫码 / 微信内打开 | 南京大学 |
| **CampusDate / SJTU Date** | 网站（trycampusdate.com） | 浏览器访问 | 上海交大 + 多校扩张中 |
| **FDU Date** | 网站 | 浏览器访问 | 复旦大学 |
| **Flip（去见一面）** | **微信小程序** | 微信搜索 / 扫码 / 分享 | 武汉大学（已开放） |
| **Tinder / 探探 / Soul** | 原生 App | 应用商店下载 | 全国（无校园限制） |
| **Summer** | 原生 App | 应用商店下载 | 全国 985/211 |
| **青藤之恋 / QsMatch** | 原生 App + 部分 H5 | 混合 | 全国（学历筛选） |

### 2.5.2 网站形态相对于 App 的 7 个结构性差异

| 维度 | App | **网站（你们）** | 影响 |
|---|---|---|---|
| **首次访问门槛** | 高（应用商店审核 + 下载 + 安装） | 低（点链接即用） | 网站获客容易，但**留下来更难** |
| **再次访问门槛** | 低（图标常驻桌面） | 高（需记住 URL 或浏览器收藏） | 网站**留存是命脉**，需主动召回 |
| **推送通知** | 原生支持，可设计为高频触达 | **几乎没有**（浏览器推送授权率 < 5%，邮件容易进垃圾箱） | **邮件 + 微信通知是唯一持久触达通道** |
| **后台运行 / 定位 / 通讯录** | 全部可用 | 全部不可用（除非用户主动允许） | 不能依赖任何后台行为信号 |
| **用户在意安装感** | 安装即"我用了这个 App" | 不安装，**心理承诺更低** | 用户更容易"忘了这个网站" |
| **桌面 vs 移动** | 移动端单一 | 双形态都得做 | 增加适配成本 |
| **被熟人撞见的尴尬** | 桌面图标暴露 | 浏览器历史可清理 | **网站在隐私层面反而更友好** |

### 2.5.3 小程序形态相对于网站的差异（Flip 等的优势）

| 维度 | **网站（你们）** | 小程序（Flip 类） | 你们的应对 |
|---|---|---|---|
| 微信内分发 | 弱（链接需复制粘贴） | **极强**（微信内一键打开） | 应做"微信分享卡片"优化 |
| 触达 | 邮件 | 服务通知（订阅消息） | **不要放弃微信生态**，做小程序版本是中长期选项 |
| 二维码扫码体验 | 跳出微信打开浏览器（差） | 微信内直接打开（好） | 短期：优化 H5 在微信内的显示；长期：考虑做小程序壳 |
| 开发成本 | 标准 Web 栈 | 微信框架，独立开发 | 不必短期切换，但应规划"小程序入口"作为 P3+ |

### 2.5.4 这些差异对 Persona 行为的修正

回顾 §3 各 Persona 时，请代入以下"网站现实"，而非 App 想象：

- **Persona A（新生）**：他**不会"打开 App 看看"**——他需要某个理由（朋友发链接、扫到海报、邮件提醒）才会再次访问。
- **Persona B（失衡专业男生）**：他**周三晚收到揭晓邮件就上一次**——其余 6 天产品在他认知里几乎不存在。
- **Persona C（研究生女生）**：她**最在意隐私的就是浏览器历史和微信扫码记录**，对网站形态的隐私优势是隐性认同。
- **Persona D（活跃女生）**：她**用桌面端的概率比 App 用户高**——意味着桌面端体验不能被忽视，但桌面端"被室友看到"是新风险。
- **Persona E（毕业季）**：他**毕业后从校园 Wi-Fi 切到家里 / 国外 IP 还能不能登录**是技术问题，必须考虑。
- **Persona F（校友）**：他**最不愿意装一个新 App**，网站形态对他反而友好——只要主域名好记。

### 2.5.5 网站形态特有的 5 个关键痛点（叠加到 §4 痛点全景）

1. **召回完全依赖邮件**：邮件送达率、打开率、是否进垃圾箱直接决定 DAU。**邮件运营是命脉**，不是辅助工具。
2. **首次访问 5 秒决生死**：没有"先安装再说"的耐心，首页加载 + 首屏价值表达必须极强。
3. **96 题问卷在网站上比 App 上更可怕**：移动浏览器的输入体验天然劣于 App，断点续填、进度保存是**生死问题**而不是 nice-to-have。
4. **登录态续期容易失效**：浏览器清缓存 / 换设备 / 关闭隐私模式都会丢登录，需要更宽松的 session 策略 + 易用的找回机制。
5. **微信内打开 vs 浏览器打开两种体验**：很多用户会先在微信里打开（受限于微信的 webview），看不到完整功能就关闭，需要做"建议在浏览器中打开"的友好提示。

## 3. 用户群体细分（6 个核心 Persona + 1 个边缘群体）

每个 Persona 包含：画像、痛点、需求层次（按强弱）、对产品的隐含要求。

---

### 🎯 Persona A：刚来南大的探索者（新生）
**代号**：周可，大一，仙林，专业未分流，单身。

**画像**：
- 18-19 岁，开学 2-3 周，迷茫期。
- 室友未必投缘，社团尚未选定，对南大本地文化（食堂口碑、自习室攻略、二手交易渠道、公选课"水"与不水）一无所知。
- 高中没谈过恋爱，对"恋爱"有想象但无经验。
- 父母管教延伸到大学（朋友圈被父母看着），社交动作要克制。

**痛点**：
- 缺"南大本地知识"——比官方新生指南更具体、比微信群更可信。
- 室友 / 班级 = 强制社交，但**无法选择**，互不投缘也无法换。
- 对 dating App 有道德焦虑（"刚开学就找对象会不会被看不起 / 被父母发现"）。
- 极易感到孤独，但不敢主动认识陌生人。

**需求层次**（按强度排序）：
1. **找信息** —— 强（哪门课好选、哪家食堂好吃、宿舍空调怎么修）
2. **找朋友 / 同好** —— 强（同样想去先锋书店、同样想加摄影社的人）
3. **找暧昧 / 恋爱探索** —— 中（好奇但不主动）
4. **严肃恋爱** —— 弱

**对产品的隐含要求**：
- **首要前门必须是"找朋友"，不是"找对象"**——否则首次访问即关闭。
- 信息流要有 UGC 内容，而不是空白匹配池——不能只在周三晚 8 点活一次。
- 圈子需要"院系 / 选修课 / 校区"等天然分类。
- "新生引导（Onboarding Tour）"必须把南大本地文化解释清楚（揭晓节奏、双选机制、各模式区别）。
- **网站现实**：他不会主动收藏 URL，必须靠**新生季二维码海报 + 院系微信群分享 + 室友推荐链接**三件套获取首访，并通过"加入微信公众号 / 订阅邮件提醒"完成召回。

### 🎯 Persona B：男女失衡专业的男生
**代号**：陈昊，大二，仙林，计算机系，单身想恋爱。

**画像**：
- 20 岁，已经在南大一年，对校园熟悉。
- 班级 30 人，男生 27 人。日常生活几乎不接触女生（除了跨院选修课偶遇）。
- 对自己的"形象 / 谈吐 / 性格"信心不高，倾向用"我学习好"作为唯一筹码。
- 暗恋过 1-2 个女生，无果。
- 朋友圈男生为主，"找女朋友"是高频群聊话题，被起哄压力大。

**痛点**：
- **线下基本无认识同校女生的渠道**（社团活动 1 学期 1 次，杯水车薪）。
- 在 Tinder / 探探等平台上配对率极低，进一步打击自信。
- **匹配失败是高频负反馈来源**——SJTU 男生 39% 成功率意味着 60% 的男生每周三晚收到"无人匹配"通知，**心理代价极高**。
- 即使匹配上，**不知道怎么聊**（"破冰焦虑"），于是匹配 → 加微信 → 三句话冷场 → 永久消失。
- 怕"用了 dating App 还失败"被同学群嘲。

**需求层次**：
1. **严肃恋爱探索** —— 强
2. **找异性朋友（哪怕只是聊天）** —— 强（但羞于承认）
3. **提升自我表达能力（写资料、聊天技巧）** —— 强（但不会主动求助）
4. **自尊心保护（不被反复"无人匹配"打击）** —— 极强

**对产品的隐含要求**：
- **落选周必须有补偿机制**，否则会持续打击自尊心，最终他会**主动忽略每周三的揭晓邮件**——这就是网站语境下的"卸载"。这是 NJU Match 差异化的关键发力点之一。
- "无人匹配"页面**必须去打击化设计**——避免红色、避免"失败"字眼、提供下一步行动入口（去圈子、去答题、修改问卷）。
- 朋友模式 / 圈子模式需要让他**也能在异性密集的场景里出现**（如混合圈子、跨学院搭子任务）。
- 破冰话题 / 共答机制可以降低聊天焦虑——CampusDate 完全没做这层。
- **不公开个人匹配率**——一旦看见自己 39%，自尊崩塌。
- **网站现实**：揭晓邮件的标题文案需要去打击化（不出现"无匹配"字样），否则他直接看标题就关闭，连产品体验补偿的机会都不给你。

### 🎯 Persona C：学业压力下的研究生女生
**代号**：林书苗，研一，仙林，文学院，单身但不急。

**画像**：
- 23 岁，刚读研，组里全女、导师严格、论文压力大。
- 没用过 Tinder / 探探，对它们的"约"标签反感。
- 本科有过感情，目前不急于开始，但**害怕在博士毕业前已无社交圈**。
- 朋友圈基本是本科同学和实验室同门，社交固化。
- 对"内卷恋爱叙事"反感（"难道我读书是为了相亲？"）。

**痛点**：
- 现有平台默认"找对象"叙事，让她不愿打开——"我又不是脱单焦虑，凭什么贴这个标签"。
- **朋友 / 学伴 / 跨学科聊天对象的需求几乎没有任何产品在认真解决**。
- 实验室 + 宿舍两点一线，缺乏"出门遇见人"的场景。
- 害怕熟人撞见——南大不大，组里同学发现尴尬。
- 对算法匹配半信半疑，更倾向"看完一段文字 / 听完一个 podcast 决定要不要认识"。

**需求层次**：
1. **找深聊朋友（跨学科、有思想）** —— 强
2. **找学伴 / 共读伙伴** —— 中
3. **严肃恋爱探索（不排斥但不主动）** —— 中
4. **隐私强保护** —— 极强（决定她是否下载的硬条件）

**对产品的隐含要求**：
- **她不是"被恋爱前门吸引来的"用户，是"被朋友前门吸引来才有可能转化"的用户**。
- 产品需要清晰的"非脱单"叙事——朋友模式应该和恋爱模式**平起平坐**而不是附属。
- 隐私可控性（曝光范围、解锁渐进）是必要条件。
- 跨学科圈子比同院系圈子更有吸引力——她已经厌倦本院系。
- 文字深度展示（长答案、长寄语）比照片更有吸引力。
- **网站现实优势**：她对"装一个 dating App"有道德负担，但**访问一个网站心理负担小很多**——网站形态对她反而是优势，要在文案里强调"无需下载"。

### 🎯 Persona D：社交主动的高年级女生
**代号**：苏雯，大三，鼓楼，商学院，暧昧史丰富，目前空窗。

**画像**：
- 21 岁，外向，朋友多，社交主动型。
- 用过探探、Soul，对算法匹配半信半疑。
- 有 2-3 段短暧昧经历，目前主动断联中。
- 对自己的"颜值 / 谈吐 / 资料 PR"很有信心。
- 鼓楼校区，离仙林通勤不便，主要朋友圈在文科院系。

**痛点**：
- **池子见底**——身边男生圈基本扫过一遍。
- 对"南大男生质量"略失望，但**不愿意降低门槛去校外平台**。
- 害怕被父母 / 同学发现在用 dating App。
- 害怕匹配后被纠缠——前任曾死缠烂打 1 个月。
- 对"被算法挑中"有控制欲焦虑——希望算法解释 + 用户可调权重。

**需求层次**：

### Flip（去见一面）竞品详情

> **来源**：新浪新闻 2026.03.20 报道，武汉大学版本，微信小程序

| 维度 | Flip（去见一面） | NJU Match |
|---|---|---|
| **形态** | 微信小程序 | 网站（H5） |
| **问卷** | 66 题（价值观、生活方式、亲密关系态度） | 96 题恋爱 / 76 题朋友 |

| **揭晓内容** | 匹配结果 + **简要匹配理由** + 交换微信 | AI 寄语 + 双选确认 + 渐进名片解锁 |
| **设计理念** | 反浏览（不鼓励无尽筛选）、仪式感 | 同 |
| **关系沉淀** | 无（交换微信即结束） | 圈子 + 好友链 + 论坛（待前台化） |

**Flip 的三个关键观察**：
1. **机制高度相似于 NJU Match**——66 题问卷、周三揭晓、反滑屏设计，两者是同一范式。这说明这套范式在 985 校园里已形成共识，但也意味着**单靠"机制"无法区分**。
2. **Flip 比 NJU Match 更接近白箱算法**——给出"简要匹配理由"是一种透明化举动，用户感知"我知道为什么"（对应我们痛点 #6）。NJU Match 有 AI 寄语但尚未提供结构化匹配理由。
3. **Flip 的硬天花板**：小程序交换微信即结束，**没有任何关系沉淀机制**——这是 NJU Match 的生态层优势所在，只要圈子 + 论坛前台化，Flip 完全无法追赶。

## 7. 对 NJU Match 产品决策的具体建议

### 7.1 必须立刻做的（基于已有能力，前端释放即可）
对应 [ROADMAP_STATUS.md](ROADMAP_STATUS.md) 中的 P0-P1：

1. **圈子 + 论坛 + Teamup 前台化**——服务 Persona A、C 的核心需求（J1、J6）
2. **朋友模式与恋爱模式双前门**——服务 Persona A、C、F（J1、J4、J6）
3. **统一错误反馈 + 退出友好按钮**——服务 Persona D（J4）
4. **拉黑 / 举报入口前端化**——服务 Persona D（J4）
5. **落选周温和反馈页**——服务 Persona B（J5、J6）

### 7.2 应作为差异化主打的（中期）
1. **落选周补偿机制**——服务 Persona B（J5、J6）⚠️ 极重要，CampusDate 没做
2. **算法白箱化 + 可解释揭晓**——服务 Persona D（J2）
3. **校友 / 跨年龄模块**——服务 Persona E、F，独占场景
4. **课程 / 在地搭子**——服务全 Persona 的 J1（CampusDate 结构性做不到）

### 7.3 长期叙事建设（毕业纪念产品价值）
1. **大学四年关系档案 / 时间胶囊**——服务 Persona E、F（J7）
2. **校园共体验机制（共读、共答）**——加深 Persona C、D 的粘性
3. **行为信号补全问卷算法**——长期算法护城河

### 7.4 网站形态特有的产品决策（必须重视）

这一组建议是**网站 / H5 形态决定的、App 不需要做或形式不同的事**，CampusDate / SJTU Date / FDU Date 同样面临这些挑战，谁先做好谁先得利。

1. **邮件运营专项**（对应痛点 #10）
   - 揭晓邮件的标题文案做 A/B 测试，去打击化（避免"无匹配"字眼）
   - 邮件模板分群：男生 / 女生、首匹 / 多次落选、新人 / 老用户
   - 退信监控 + 域名信誉维护（已在 [PRODUCT_OPTIMIZATION_PLAN_USER_PERSPECTIVE.md](PRODUCT_OPTIMIZATION_PLAN_USER_PERSPECTIVE.md) 提到）
   - **每周非揭晓日的"轻邮件"**：圈子动态、新提问、节日信件——这是网站留存的主要抓手

2. **问卷断点续填 + 进度可见**（对应痛点 #11）
   - 必须 P0 上线，否则 96 题在移动浏览器上是劝退器
   - 进度自动保存（每答 1 题就保存）
   - 推荐拆分为"5 周渐进式"——首次 30 题以下完成基础匹配，剩余 6+ 周渐进解锁

3. **微信内打开优化**（对应痛点 #12）
   - 检测 UA，识别"在微信内打开"的访问，给出"建议在浏览器中打开"的友好提示（仅在功能受限时）
   - 优化分享卡片：标题、缩略图、描述要为"被同学转发"场景设计——这是你们的主要分发渠道
   - 微信内能用的功能尽量保留（避免一进来就提示跳出）

4. **桌面端 + 移动端双形态体验**
   - 移动端是主战场，所有路径必须移动优先
   - 跨设备登录态保持（浏览器清缓存 / 换设备不丢登录）

5. **二维码 + 海报分发能力**
   - 网站没有应用商店，**校园海报二维码扫码 + 院系微信群分享**是主要获客渠道
   - 二维码 landing page 应针对不同场景（新生季、节日活动、社团合作）做差异化
   - 这部分是宣传部门 / 运营的工作，已在 [PRODUCT_OPTIMIZATION_PLAN_USER_PERSPECTIVE.md](PRODUCT_OPTIMIZATION_PLAN_USER_PERSPECTIVE.md) 跨部门能力中提到

6. **小程序壳作为 P3 选项（非短期）**
   - 不必短期切换为小程序，但**评估"开发一个小程序壳指向同一后端"的可行性**
   - 这能解决：微信生态的天然分发、扫码体验、订阅消息推送
   - 注意：微信对涉及"婚恋交友"小程序的审核比网站严格得多

## 8. 风险与伦理边界

1. **男女配对率公开是禁忌**。SJTU 39%/69% 数据已经造成男生群体性挫败感。**NJU Match 不应公开个人匹配率**，落选反馈应模糊化、温和化。

2. **"高质量"叙事是双刃剑**。强调"南大学生 / 985 专属"会被解读为学历内卷帮凶。建议在文案中**强调"同校信任"而非"高学历筛选"**——这是品牌话术上的关键判断。

3. **隐私默认值要严**。所有可见性默认值应是"匹配后才解锁"而不是"公开默认"。这是 Persona D、F 下载的硬条件。

4. **性别少数议题低调处理**。架构上预留，宣传上不强调，避免触碰校园政策红线。

5. **沉没成本不能再加**。问卷题数已经 96 题，**不要再加**。建议拆分为"5 周渐进式"——每次进入答 5-10 题，长期累积形成完整画像。

6. **校园 PR 风险**。一旦发生匹配纠纷 / 骚扰事件被媒体报道，会直接影响南大形象，治理体系（[REPORT_HANDLING_SYSTEM.md](REPORT_HANDLING_SYSTEM.md)）必须 P0 上线，不能拖延。

7. **多校区差异不能忽视**。仙林 / 鼓楼 / 苏州学生的实际可见面成本不同，匹配应支持"是否限制本校区"选项。

8. **网站形态特有的合规风险**。涉及婚恋的网站需要做好 ICP 备案、隐私协议、未成年人保护等合规要素——大学生群体年龄边界（个别新生 17 岁）需要特别注意。如果未来开小程序，微信审核对"婚恋交友"类目要求 ICP + 公司主体资质。

## 9. 推荐的下一步调研动作（一手数据补全）

为符合 [P1/P1-需求分析.md](P1/P1-需求分析.md) 要求，建议第一组在 P1 阶段执行：

### 9.1 问卷设计（针对本文档识别的 6 个 Persona）
- **基础题**：年级、性别、院系、单身状态、过往恋爱经验
- **Persona 识别题**：参与意图（恋爱 / 朋友 / 搭子 / 看热闹）、社交能力自评、隐私敏感度
- **痛点验证题**：对周更频率的接受度、对落选周补偿的需求度、对朋友模式的兴趣度、对熟人撞见的担忧度
- **JTBD 验证题**：在不同情绪状态下"会打开 App"的概率（孤独时？落选后？匹配后？空窗时？）

### 9.2 访谈对象配置（4 人 = 6 Persona 中选 4 个）
建议优先访谈：
- 1 × **Persona B**（失衡专业男生）—— 最痛苦群体，也是最容易流失的
- 1 × **Persona C**（研究生女生）—— 最被忽视群体，也是双前门策略的验证目标
- 1 × **Persona D**（社交活跃女生）—— 最挑剔群体，最能挑出产品问题
- 1 × **Persona E 或 F**（毕业季 / 校友）—— 差异化机会群体

### 9.3 验证关键假设
- **H1**：朋友模式作为前门会扩大 30% 以上的潜在用户基数（验证 Persona C 的转化）
- **H2**：落选周补偿机制能将男生留存率从行业平均 ~20% 提升到 40%+（验证 Persona B 的留存）
- **H3**：圈子前台化能将"非揭晓日"DAU 提升 3 倍以上（验证 J1）
- **H4**：校友模块能解锁本科外的细分用户群（验证 Persona F 的市场存在）
- **H5（网站形态相关）**：邮件打开率 + 点击率是网站留存的关键指标，应稳定在打开率 > 40% / 点击率 > 15%
- **H6（网站形态相关）**：通过校园海报二维码扫码进入的用户，问卷完成率应高于通过链接分享进入的用户

### 9.4 调研后回填本文档
P1 完成后，将一手数据回填本文档第 1 节"数据来源"和第 3 节"用户群体"对应字段，并更新 9.3 假设的验证结论。
