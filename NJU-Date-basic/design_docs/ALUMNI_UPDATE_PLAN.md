# 匹配机制后更新记录与计划预案（校友/毕业生适配）

> *注：为了不干扰本周进行的常态匹配与已有用户数据状态，以下所有的更新需在本周三晚匹配结算并完全下发结果后（即“本周匹配后”）进行开发与部署。*

## 核心更新目标：引校友（毕业生）适配机制
由于拥有 `smail` 邮箱的校友/毕业生希望加入匹配，针对在校生的默认题目往往不适合于进入职场或继续深造的校友。本次更新的核心在于在**身份定义、问卷语境和算法兼容上**全面支持“毕业生”选项。

### 1. 个人档案系统 (Profile) 更新
- **阶段下拉/选项扩展**：
  将 `个人档案` 中的 `当前年级` 或 `身份阶段` 新增一栏「**毕业生**」。
  *(附注：UI 及表单验证需要支持接收“毕业生”作为独立有效值，并将其持久化到后端 `schema.ts` 结构中。)*

### 2. 动态问卷 (Survey) 语境适配
通过读取当前登录用户的档案身份（如当前值为“毕业生”时），前端渲染的问卷文案需进行动态适配：
- **地域/发展地问题：**
  - 【在校生】：*“未来倾向发展的省份或地区？”*
  - 【校友】：*“目前所在/工作的省份、城市或地区？”*
- **匹配偏好问题：**
  - *“希望匹配对象的年级”*选项必须包含并兼容「毕业生」，允许校友选择“只和校友匹配”或“不限年级”。
- **距离/接受度问题：**
  - 【在校生】：*“是否接受跨校区恋爱？”*
  - 【校友】：*“是否接受不同工作城市/异地发展？”*

### 3. 数据层与匹配算法 (Matching Algorithm) 修改点
- **后端模型校验 (`frontend`/`backend` 验证)**
  - Zod 枚举需同步更新，纳入“毕业生”标签，避免后端报 Schema Validator Error 400。
- **Gale-Shapley (`galeShapley.ts` 与 `compatibility.ts`) 平滑过渡**
  - **年级过滤池**：修正双方筛选逻辑。确保“希望匹配的年级包括毕业生”和“我是毕业生”能够正确交集验证。（如排斥毕业生则需硬拦截）。
  - **异地换算逻辑**：原逻辑中的跨校区权重（例如仙林、鼓楼相互接受度），在毕业生身上可能直接升级为真正意义上的“跨市异地”，或者视为校外，需确保兼容度函数不会出现未知权重导致 `NaN` 崩溃。

### 4. 其他 UI 及文案优化
- 在结果揭晓页 (`Reveal.tsx`) 与 对象档案查阅卡片中，对身份标签进行高亮，明确展示它为“毕业生”。
- 完善提示语（Tooltip 等），若检测到用户有在校生转变为了“毕业生”，弹窗提示其更新问卷中的地域与距离偏好。
