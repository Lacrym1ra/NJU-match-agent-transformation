# NJU Match 用户视角完整改进方案（含跨部门能力）

## 1. 文档目的与边界

本方案用于指导产品、研发、宣传、运维协同升级，目标是提升用户体验、留存、稳定性与运营效率。

安全边界：
- 本文不包含任何密钥、管理员口令、生产主机地址、数据库凭据。
- 涉及高风险操作仅描述能力需求与权限流程，不给出敏感配置细节。

---

## 2. 当前用户旅程评估

### 2.1 已有能力（可保留）

- 登录/注册、建档、问卷、仪表盘、揭晓、双选、历史记录主流程完整。
- 每周固定节奏（匹配与揭晓）形成仪式感，具备“周更”产品特征。
- 问卷版本化机制已具备，便于后续做增量更新与召回。
- 管理端已有统计、匹配触发、邮件相关功能基础。

### 2.2 高频用户痛点

- 关键页面存在静默失败，用户缺少明确错误反馈与恢复路径。
- 等待与揭晓阶段反馈颗粒度不足，用户感知“系统没动”。
- 圈子（circles）后端能力已存在但前端未完整接入，留存潜力未释放。
- 社交合规后端能力已具备，但前端入口未完整接入，用户目前还看不到拉黑/举报按钮。
- 机制认知需统一："已匹配排除"用于防重复配对，"拉黑"用于跨场景隔离与安全边界，两者应并行而非互相替代。
- 管理能力与跨部门操作仍偏技术化，非研发同学使用门槛高。

---

## 3. 升级目标（12周）

- 用户体验：减少无反馈操作，关键路径成功率可视化。
- 业务增长：提升问卷完成率、揭晓到达率、双向率、次周留存。
- 组织效率：让宣传、运维在权限内“一键完成”高频动作。
- 安全合规：开发执行不接触核心安全信息。

---

## 4. 功能升级路线图（P0-P3）

## P0（第1-2周）：稳定与信任底座

1. 统一错误反馈层
- 仪表盘、问卷、揭晓、设置页统一加载态/错误态/重试入口。
- 所有关键失败必须有用户可见提示。
- 前置任务：建立全局 Toast/Notification 组件，统一 API 错误拦截层。

2. 登录后路由状态机统一
- 统一由后端返回状态机字段，前端按状态机跳转。
- 消除”跳错页、来回跳”的体验问题。

3. 移动端适配审查
- 关键页面（问卷填写、揭晓拆信、仪表盘、设置）移动端体验审查与修复。
- 学生群体 80%+ 在手机端使用，确保触控交互、响应式布局、输入体验流畅。
- 揭晓页拖拽拆信封在移动端需适配 touch 事件。

4. 管理操作可审计
- 关键操作记录操作人、时间、动作、结果。
- 支持后续追责与复盘。

5. 运营关键动作预检
- 匹配触发、群发前先做前置检查（人数、模板状态、时间窗口）。
- 预检失败时阻断操作并给出原因。

6. 社交合规与举报机制（新增）
- 增加匹配后”拉黑/举报”入口，阻断恶意骚扰。
- 增加”账号注销（数据匿名化）”功能：按用户诉求剥离学号、姓名、联系方式等 PII（个人身份信息），保留匿名特征数据用于匹配模型训练与漏斗分析。

## P1（第3-6周）：留存与跨部门提效

1. 问卷断点续填与进度保存
- 60 道灵魂问卷需支持中途退出后恢复进度（参考档案 `PATCH /user/profile/draft` 模式）。
- 前端显示清晰的进度条与预计剩余时间。
- 中断后再次进入时弹出”继续上次填写”提示。

2. 圈子前台化（技术细节详见 `CIRCLE_DESIGN.md`、`CIRCLE_API.md` 及 `CIRCLE_MODULE_PLAN.md`；搭子匹配算法详见 `backend/docs/CIRCLE_MATCHING_ALGORITHM.md`）
- 上线圈子入口、加入、圈内问卷（带频道特定标签）、圈内匹配、圈内历史。
- 在仪表盘增加”我的圈子”卡片与周状态。
- 落地上线好友链路工具与联系方式解锁机制，增加社交门槛。

3. 等待期与落选体验增强
- 展示匹配进度信息（非隐私聚合数据）。
- 提供提醒配置与确认反馈。
- 落选温和引导：若用户本周”轮空”，给出模糊化的温和建议（如：”你的筛选条件可能较为严格，建议适当放宽距离或年级偏好”），引导修改问卷。注意：不暴露匹配池具体规模或精确百分比，避免隐私争议。
- 从历史记录”止步”状态提供直接跳转修改问卷的入口。

4. 首次使用引导（Onboarding Tour）
- 新用户首次进入仪表盘时，显示 3-5 步功能引导。
- 解释”每周三 20:00 揭晓”的产品节奏、问卷填写意义、双选机制。
- 降低新用户认知门槛，提升问卷完成率。

5. 校友/毕业生适配（详见 `design_docs/ALUMNI_UPDATE_PLAN.md`）
- 档案系统支持”毕业生”身份选项。
- 问卷文案按身份动态适配（地域问题、距离问题）。
- 匹配算法兼容毕业生标签，确保年级过滤池与异地权重正确处理。

6. 宣传部门一键运营能力
- 一键发送宣传邮件（模板化、分群、可预览、可回滚）。
- 一键发送站内公告（首页横幅/弹窗，设置开始结束时间）。
- 邮件任务支持”灰度名单先发 + 全量发布”。
- 退信监控与自动暂停：批量邮件送达率过低时自动暂停任务，避免影响域名信誉。

7. 运维部门一键维护能力
- 一键开启维护模式（前台切维护页、API 进入只读或白名单模式）。
  - 注：当前已有基于 Nginx 配置的手动维护方案（见 `backend/docs/MAINTENANCE_MODE.md`），目标是升级为 API 驱动的一键操作。
- 一键关闭维护模式并恢复正常流量。
- 一键查看系统健康摘要（服务状态、错误率、邮件队列状态）。

## P2（第7-10周）：增长飞轮与精细化运营

1. 问卷策略优化
- 分意图动态题目深度。
- 降低高跳出题目摩擦。

2. 揭晓后互动引导
- 提供首聊建议卡、破冰话题、互动建议。
- 增加”48小时互动打卡”轻引导。
- 揭晓页”错过”处理：用户未在揭晓当晚查看时，次日打开仪表盘应有明确提示”你有一封未读锦书”。

3. 匹配历史情感化增强
- “往事回溯”页面补充当时的契合度分数与 AI 寄语回顾。
- 增加情感厚度，提升用户对平台的情感连接。

4. 宣传运营自动化
- 关键节点自动触发运营模板（周三揭晓、节日活动）。
- 支持 A/B 主题文案测试。

5. 运营看板
- 构建漏斗看板：注册 -> 建档 -> 问卷 -> 参与 -> 揭晓 -> 双向。

## P3（第11-12周）：工程化与长期稳定

1. 自动化测试覆盖核心链路。
2. 监控告警覆盖核心业务指标。
3. 发布冻结与回滚机制完善（关键时段避免风险发布）。
4. 基础无障碍性（Accessibility）审查。
   - 键盘导航支持、屏幕阅读器兼容。
   - 揭晓页暗色主题 + 南大紫的色彩对比度验证（WCAG AA 标准）。

## 5. 跨部门能力设计（重点新增）

### 5.1 宣传部门（Marketing/PR）

目标：不依赖研发，完成安全可控的运营触达。

建议能力：
1. 一键发送宣传邮件
- 选择模板、选择人群、发送时间（立即/预约）。
- 发送前预览与样本发送。
- 发送后展示成功/失败统计。

2. 一键发布活动公告
- 渠道：首页横幅、仪表盘公告、登录页提示。
- 支持时间窗、优先级、下线时间。

3. 活动追踪
- 点击率、打开率、转化率（问卷完成/回访/双向）。

权限原则：
- 宣传角色仅能操作模板化内容与受控人群。
- 不可接触管理员密钥、系统配置、数据库查询能力。

### 5.2 运维部门（Ops/SRE）

目标：快速止损、低风险运维。

建议能力：
1. 一键维护模式
- 开启后：
  - 前端展示 maintenance 页面。
  - 非关键 API 暂停写操作。
  - 管理白名单保留必要诊断接口。
- 关闭后自动恢复服务。

2. 一键健康检查
- 输出服务状态、依赖可用性、任务队列、最近错误摘要。

3. 一键任务开关
- 允许在紧急场景暂停/恢复定时任务（匹配、邮件批处理）。

权限原则：
- 运维角色可操作运行态开关，不可读取业务敏感内容。
- 所有变更进入审计日志。

### 5.3 客服/运营支持（必备能力）

目标：安全、快速地处理用户工单（诸如：学号填错申诉、状态流转异常等）。

建议能力：
1. 用户状态脱敏查询：
- 仅允许通过学号/外部ID查询用户的“平台生命周期状态”（未认证/问卷中/匹配中/被拉黑等）。
- 严格遮蔽问卷具体作答项与隐私数据。

2. 账号状态干预：
- 提供基本的工单处理动作，例如：“重置建档状态”、“断开异常匹配”。

## 6. 关键指标与验收标准

核心指标：
- 问卷完成率
- 揭晓页到达率
- 双向率
- 次周留存率
- 页面错误率
- 管理操作成功率

跨部门指标：
- 宣传邮件发送任务成功率
- 活动公告发布时效
- 维护模式切换时长
- 故障平均恢复时间（MTTR）

阶段验收：
- P0：关键页面无静默失败，统一错误反馈上线。
- P1：宣传一键发送、运维一键维护能力可用并可审计。
- P2：运营自动化与漏斗看板稳定运行。
- P3：测试与告警覆盖关键链路。

---

## 7. 风险与治理

主要风险：
- 跨部门能力开放后误操作风险提升。
- 新功能并行上线导致回归风险。

治理策略：
- RBAC 最小权限。
- 所有高风险动作二次确认。
- 灰度发布与回滚预案。
- 高峰时段发布冻结。

---

## 8. 实施建议

- 先做 P0，再做跨部门一键能力（P1），避免在不稳定底座上扩能力。
- 宣传与运维能力优先走“模板化 + 预检 + 审计”的产品路径。
- 所有跨部门能力必须“可撤销、可追踪、可限制范围”。
