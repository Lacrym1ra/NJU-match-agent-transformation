## 整体流程

```
每周三 18:00 CST
        │
        ▼
  Phase 0: 资格筛选
  （isParticipating + profileComplete + surveyComplete）
        │
        ▼
  Phase 1: 按性别偏好分池
  （减少计算量：N×N → Σ Mᵢ×Kᵢ）
        │
        ▼  ← 对每个池单独执行 ──────────────────────────────┐
  Phase 2: Dealbreaker 硬过滤                               │
  （性别偏好 / 恋爱目的 / 年龄 / 年级 / 校区 / 专业 / 家乡）    │
        │                                                   │
        ▼                                                   │
  Phase 3: 相容度评分 → [0, 1]                               │
  （Likert × 4维度 + Jaccard + Spearman + 分类 + MBTI + 偏好）│
        │                                                   │
        ▼                                                   │
  Phase 4: 贪心最优匹配 + 增广路径救援                         │
  （最大化总分 → 最大化配对人数）                         ──────┘
        │
        ▼
  Phase 5: AI 生成缘分卡片文案
        │
        ▼
  写入数据库，状态 LOCKED
        │
每周三 20:00 CST
        │
        ▼
  解锁 → 状态 REVEALED，用户可查看
```

## Phase 0 — 资格筛选

**文件：** `matchService.ts`

用户需同时满足以下三个条件才参与本周匹配：

| 字段 | 条件 |
|------|------|
| `isParticipating` | `true`（本周主动报名） |
| `profileComplete` | `true`（基础信息已填写） |
| `surveyComplete` | `true`（问卷已完成） |

同时还需要 `gender` 和 `genderPref` 字段不为空。

---

## Phase 1 — 分池

**文件：** `matching/pools.ts`

将所有参与者按 `(gender, genderPref)` 组合分组，找出互相兼容的组对，构成匹配池。每个池内只有 GroupA 和 GroupB 两组，后续算法在池内运行。

**分池逻辑：**

```
对每对 (groupKey_A, groupKey_B)：
  若 A 接受 B 的性别 AND B 接受 A 的性别 → 构成一个池
  避免重复（pairKey 排序去重）

特殊情况（如 male→male × male→male）：
  随机打乱后对半拆分，分别充当 GroupA / GroupB
```

**示例池：**

| Pool | GroupA | GroupB |
|------|--------|--------|
| 异性恋 | male→female | female→male |
| 男同 | male→male（前半） | male→male（后半） |
| any 偏好 | 含 any 的各组 | 对应能接受的组 |

分池的意义：将 O(N²) 的全量比较拆分为多个小规模 O(Mᵢ×Kᵢ) 计算。

## Phase 2 — Dealbreaker 过滤

**文件：** `matching/dealbreakers.ts`

基于**红线理论(Dealbreakers效应)**，极严硬筛，宁缺毋滥。以下任一条件不满足，配对直接淘汰，不进入评分阶段。

### 2.1 性别偏好（双向）

```
A 接受 B 的性别 AND B 接受 A 的性别
```

### 2.2 基础硬约束

| 检查项 | 规则 | 相关题目 / 字段 |
|--------|------|---------|
| **年龄范围** | 双方出生年份必须在对方指定范围内，双向检查 | q1, q2 |
| **同乡** | 任一方要求“必须和我同乡”，但家乡省份不同则淘汰 | q3, q4 |
| **跨校** | 结合画像，任一方不接受跨校则淘汰 | 画像, q6 |
| **年级要求** | 结合画像，若一方不能满足另一方的年级偏好则淘汰 | 画像, q5 |
| **专业硬要求** | 若选“一定同学院”或“一定不同学院”，结合画像进行绝对排斥 | 画像, q7 |

### 2.3 生活方式红线 (核心冲突)
遇到以下绝对的生活方式冲突，直接淘汰：
*   **抽烟**：一方吸烟 (`q9`=是) + 另一方 100% 无法接受 (`q10`=彻底不能接受)
*   **饮酒**：一方非滴酒不沾 (`q11`=不是) + 另一方要求伴侣滴酒不沾 (`q12`=是)
*   **宠物**：一方一定要养 (`q13`=是) + 另一方完全不接受 (`q14`=不是)

### 2.4 核心题极端分歧

针对部分核心的底线 7 分制 Likert 题：

```
若任一方将某题标注为"非常重要"（importance = 3）
AND 双方答案差值 ≥ 5（满分最大差值为 6）
→ 淘汰
```

## Phase 3 — 相容度评分

**文件：** `matching/compatibility.ts`
**输出：** `score ∈ [0, 1]`（保留 2 位小数）及各维度分项

所有通过 Dealbreaker 过滤的配对，计算一个综合相容度分数。

---

### 3.1 Likert 核心维度（基于 OkCupid 加权距离变体）

现将题目调整为三个主要维度，包含 1-7 分 Likert 题。

**单向满意度（A 对 B）：**

$$\text{oneWay}(A \to B) = 1 - \frac{\sum_i w_i \cdot |a_i - b_i|}{\sum_i w_i \cdot 6}$$

其中 $w_i$ = A 对第 $i$ 题标注的重要程度（1=一般 / 2=比较重要 / 3=非常重要）。

**双向维度得分：**

$$\text{dimScore} = \frac{\text{oneWay}(A \to B) + \text{oneWay}(B \to A)}{2}$$

**各维度说明：**

| 维度 | 说明 |
|------|------|
| `values` 价值观 | 包含做事风格、阶级观念、事业爱情、善与聪明等核心权衡题 |
| `lifestyle` 生活习惯 | 包含消费观、整洁度、计划性、辣度等 |
| `emotional` 情感边界 | 包含冷战处理、查手机、出轨观点、占有欲、异性闺蜜等高压题 |

---

### 3.2 多选题 Jaccard 相似度

题目：`q8`（核心兴趣）、`q29`（看重的品质）

$$\text{Jaccard}(A, B) = \frac{|A \cap B|}{|A \cup B|}$$

所有多选题取平均后，以一定基础权重计入总分。

---

### 3.3 爱的语言 Spearman 等级相关 (Q59)

针对 `q59` (5种爱的语言排序)：

$$\rho = 1 - \frac{6 \sum d_i^2}{n(n^2 - 1)}, \quad \text{归一化} = \frac{\rho + 1}{2}$$

以此反映两人感受和表达爱意的频段是否相通。

---

### 3.4 Q60 核心价值放大器 (Core Value Alignment)

**关键改动**：
匹配算法考虑到了优先级的差异。若某用户在 `q60`（即“在所有维度中，你认为哪一项在匹配中最重要”）中选择了 `values`、`lifestyle` 或 `emotional` 之一，在这两大类积分项汇成总分时，**对应的维度权重将被放大 (Multiplier = 1.5)**。

这将非常显著地使得总分受用户“核心诉求”主导，进而增加高分群体的匹配质量。


$$\rho = 1 - \frac{6 \sum d_i^2}{n(n^2 - 1)}, \quad \text{归一化} = \frac{\rho + 1}{2}$$

权重 **0.8**。

---

### 3.4 分类题对齐

题目：`q3, q8, q10, q18, q29, q47, q52`

逐题比较是否完全相同，取均值后以权重 **0.8** 计入。

$$\text{catScore} = \frac{1}{n} \sum_i \mathbb{1}[a_i = b_i]$$

---

### 3.5 MBTI 兼容度

**文件：** `matching/compatibility.ts`，查表替代字母计数法。

使用 16×16 对称矩阵，分 5 档：

| 颜色 | 分数 | 含义 |
|------|------|------|
| 🔵 蓝 | **1.00** | 通常是理想的绝配 |
| 🟢 绿 | **0.75** | 有好的机会建立亲密关系 |
| 🟡 黄 | **0.60** | 单方面很合适，易发展为舔狗 |
| 🟠 橙 | **0.50** | 可能成，但不是最佳选择 |
| ⬜ 灰 | **0.30** | 需要再仔细想一想 |

部分关键配对示例：

| 组合 | 档位 | 典型说明 |
|------|------|---------|
| INFP ↔ ENFJ | 🔵 | NF 互补绝配 |
| ENFP ↔ INFJ / INTJ | 🔵 | 直觉主导互补 |
| INFJ ↔ ENTP | 🔵 | Ni-Fe vs Ne-Ti 互补 |
| INTJ ↔ ENTJ | 🔵 | NT 内部高度契合 |
| ISFP ↔ ISFJ / ESTJ | 🔵 | SP-SJ 感知互补 |
| NT ↔ SP | 🟡 | 吸引但可能不平衡 |
| NT ↔ SJ | 🟠 | 逻辑与规则的摩擦 |
| 跨气质冷组合 | ⬜ | 基础差异较大 |

同类型（如 INFP ↔ INFP）返回 0.5（中性）。

MBTI 以权重 **1.0** 计入总分。

---

### 3.6 显式偏好加成

根据双方填写的具体偏好与实际情况对比打分，取双向平均后加入总分。

| 偏好类型 | strict_same | prefer_same | prefer_cross / avoid | 无偏好 | 权重 |
|----------|-------------|-------------|----------------------|--------|------|
| 专业（q58） | 同=1.0 / 异=0 | 同=1.0 / 异=0.4 | 同=0.3 / 异=1.0 | 0.7 | 0.9 |
| 校区（q59） | 同=1.0 / 异=0 | 同=1.0 / 异=0.5 | 同=0.4 / 异=1.0 | 0.7 | 0.9 |
| 家乡（q13） | 同=1.0 / 异=0 | 同=1.0 / 异=0.5 | — | 0.7 | 0.7 |

---

### 3.7 最终得分公式

$$\text{score} = \frac{\sum_k w_k \cdot s_k}{\sum_k w_k}$$

各分项汇总（有数据时才参与计算）：

| 分项 | 最大权重 |
|------|---------|
| values 维度 | 2.0 |
| emotional 维度 | 1.8 |
| lifestyle 维度 | 1.6 |
| attraction 维度 | 1.2 |
| 多选题（Jaccard） | 1.0 |
| MBTI 兼容度 | 1.0 |
| 专业偏好 | 0.9 |
| 校区偏好 | 0.9 |
| 排序题（Spearman） | 0.8 |
| 分类题对齐 | 0.8 |
| 家乡偏好 | 0.7 |
| **理论满分权重合计** | **11.7** |

最终输出保留 2 位小数，范围 `[0, 1]`，同时返回四个维度的分项得分。

## Phase 4 — 贪心最优匹配

**文件：** `matching/galeShapley.ts`（函数名：`greedyMaxWeightMatching`）

目标：在所有可能的配对方案中，找到**帕累托最优**的分配——不存在另一种方案能让所有人至少不变差而某人更好。

### 4.1 贪心阶段

```
1. 收集所有 score > 0 的有效配对，排序：score 降序
2. 遍历排序列表：
   若配对双方均未匹配 → 立即配对
   否则跳过
```

**特性：** 高分配对优先分配，自然最大化总权重（总相容度之和）。

### 4.2 增广路径阶段

贪心阶段后，部分用户可能因"高分配对提前锁定了某个 receiver"而错失匹配机会。增广路径阶段修复此问题。

对每个未匹配的 proposer，执行 DFS 寻找增广路径：

```
augment(p, visited):
  对 p 的所有候选 receiver r（按 score 降序）：
    若 r 未访问：
      标记 r 为已访问
      若 r 当前未匹配 OR augment(r 当前匹配者, visited) 成功：
        将 p 匹配到 r（重新分配）
        return true
  return false
```

**特性：**
- 不降低总得分（只对未匹配者尝试增广）
- 最大化配对人数（最大基数匹配）
- 每人最多被重新分配一次

### 4.3 复杂度分析

| 操作 | 复杂度 | N=5000 估算 |
|------|--------|------------|
| 评分计算 | O(N²) | ~25M 次，＜1 min |
| 排序 | O(N² log N) | 可忽略 |
| 贪心分配 | O(N²) | 极快 |
| 增广路径 | O(V·E) | 稀疏图下接近 O(N²) |
| **总计** | **O(N² log N)** | **适合万级用户** |

> 对比：匈牙利算法为 O(N³)，N=5000 需约 34 小时，不可用。

## Phase 5 — AI 缘分卡片

**文件：** `services/aiService.ts`

每对匹配成功的用户，调用 AI 服务根据双方问卷答案和相容度分数，生成一段个性化的"缘分寄语"，存入 `matches.curatorNote`。

若 AI 服务调用失败，回退文案：`"你们的故事即将开始，让我们拭目以待。"`

## 统计指标

每次匹配完成后，`runMatchingPipeline` 返回以下统计数据，写入日志：

| 字段 | 含义 |
|------|------|
| `totalParticipants` | 本周参与人数 |
| `matchedPairs` | 成功配对数 |
| `unmatched` | 未匹配人数 |
| `matchRate` | 匹配率 = matchedPairs × 2 / totalParticipants |
| `avgCompatibilityScore` | 所有配对的平均相容度分数 |
| `weightLoss` | 未匹配用户各自最优可能分数之和——反映 dealbreaker 设置是否过严 |

> **`weightLoss` 使用指南：** 若该值持续偏高，说明有大量潜在高分配对因 dealbreaker 被过滤或因池内比例不均衡而流失，可以考虑放宽某些硬约束或调整问卷选项。

## 扩展问卷

**文件：** `matching/surveySchema.ts`

所有题目 ID 集中在此文件管理，匹配代码从 schema 读取，无需手动修改算法文件。

### 新增普通题目

| 题目类型 | 操作 |
|----------|------|
| Likert（1-7 分） | 追加 ID 到 `DIMENSIONS` 对应维度数组 |
| 多选 | 追加到 `MULTI_SELECT_QUESTIONS` |
| 排序 | 追加到 `RANKING_QUESTIONS` |
| 分类（单选对比） | 追加到 `CATEGORICAL_QUESTIONS` |
| 严格 dealbreaker | 追加到 `STRICT_LIKERT_QUESTIONS` |

### 新增特殊逻辑题目（dealbreaker / 偏好）

1. 在 `Q` 常量对象中添加命名 ID：
   ```typescript
   export const Q = {
     // ...现有字段
     NEW_PREF: 'q99',
   } as const;
   ```
2. 在 `dealbreakers.ts` 或 `compatibility.ts` 中实现对应逻辑。

### 更新 MBTI 矩阵

如需调整 MBTI 配对分数，直接修改 `compatibility.ts` 中的 `MBTI_COMPAT` 矩阵。行列顺序为：

```
INFP ENFP INFJ ENFJ INTJ ENTJ INTP ENTP
ISFP ESFP ISTP ESTP ISFJ ESFJ ISTJ ESTJ
```

## 未来改进计划 (Roadmap)

### 策略 B：基于 AI 的文本级兴趣匹配
当前问卷对爱好的具体信息获取采用"纯文本自主填写"（q8_1, q8_2, q8_3），并通过策略 A 存入数据库中，旨在收集用户的原始偏好作为资料页破冰展示，不参与初期分数计算。

由于底层架构完全兼容，在下个大版本迭代中，**可以平滑升级为算法计分（策略 B）**：
1. **预处理清洗方案：** 当用户在前端提交新问卷时，在后端的 surveyService.ts 结合 AI 调用将其转化为结构化标准标签。
2. **动态匹配方案：** 或者在 compatibility.ts 的算法内，引入轻量化本地 / 远端的大模型向量距离比对，计算例如"J-POP"和"日本流行音乐"之间的高维度相似性得分。
此迭代前端和数据库 **无须进行修改**。
