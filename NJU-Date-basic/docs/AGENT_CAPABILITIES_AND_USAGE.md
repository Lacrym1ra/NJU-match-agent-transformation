# NJU Match Agent：当前能力与使用指南

> 本文对应当前 P0/P1 实现。Agent 是面向用户的站内协作入口，不是绕过原业务权限的管理员。所有读取均以当前登录用户身份执行；会产生真实数据变化的操作均需要显式确认。

## 1. 使用入口

### 全局悬浮 Agent

- 登录后，在任意支持页面点击右下角 `Agent` 悬浮按钮。
- 快捷键：`Alt + A` 打开或收起。
- 悬浮 Agent 会携带当前页面的类型和资源编号，并在后端重新执行权限检查后读取页面内容。
- 点击右上角“展开”可进入完整 Agent 工作台。

### 完整 Agent 工作台

- 地址：`/agent`
- 与悬浮 Agent 共享最近的会话记录和待确认操作。
- 额外提供帖子草稿表单、完整结果卡片和检索依据。

## 2. Agent 能力总览

| 模块 | 读取/辅助能力 | 可执行操作 | 确认要求 |
|---|---|---|---|
| 资料与问卷 | 读取完成状态、缺失项数量，作为推荐依据 | 不代填资料和问卷 | — |
| 圈子 | 搜索、推荐、读取当前圈子详情 | 发送加入申请 | 必须确认 |
| 圈内茶话 | 读取当前圈子最近 20 条、用户有权查看的消息 | 发送用户明确给出的消息 | 必须确认 |
| 论坛 | 搜索帖子、读取当前帖子正文和评论、读取我的帖子/点赞/收藏 | 草稿、发布、评论、点赞、收藏 | 草稿不需确认；其余必须确认 |
| 搭子/组队 | 在已加入圈子中检索组队、读取当前组队详情和成员可见群聊 | 直接加入、提交申请、发送组队群聊 | 必须确认；加入时联系方式由用户本人填写 |
| 匹配 | 读取当前用户自己的匹配状态和对方公开资料 | 接受或拒绝当前可操作匹配 | 必须确认 |
| 通知 | 读取最近通知或未读通知 | 单条已读、全部已读 | 必须确认 |
| 页面感知 | 读取当前帖子、圈子、圈聊、组队、组队群聊、匹配页面上下文 | 根据页面生成绑定到当前资源的操作 | 写操作必须确认 |

## 3. 推荐指令样例

### 3.1 圈子与论坛检索

```text
根据我的资料和问卷，推荐最多 3 个学习圈子和 3 篇帖子。
查找与 Agent、LLM 和工具调用有关的圈子。
帮我找本周可以参加的校园活动。
找一些适合长期交流的学习搭子。
```

Agent 只会引用真实检索结果。圈子使用 `[C1]`、帖子使用 `[P1]`、组队使用 `[T1]` 等可验证引用。

### 3.2 加入圈子

```text
帮我加入“AI 与 Agent 学习圈”。
```

执行流程：

1. Agent 检索并解析完整圈名。
2. 页面显示“申请加入”操作。
3. 用户确认。
4. 自由加入圈直接成为成员；审核圈生成待审核申请。

Agent 不会绕过审核、黑名单、圈子状态或重复申请检查。

### 3.3 圈内茶话读取与发送

在圈内茶话页面可以询问：

```text
总结最近的讨论，列出大家提出的三个主要问题。
根据最近的聊天，帮我拟一条礼貌的回复。
```

明确发送：

```text
在“AI 与 Agent 学习圈”的圈内茶话发送：今晚有人一起交流工具调用吗？
```

只有当前用户是活跃圈成员时才能读取和发送。消息仍会经过原聊天内容审核、关键词规则、幂等和频率限制。

### 3.4 帖子草稿与发布

自然语言格式：

```text
发帖：周末 Agent 共读｜周六晚一起读工具调用论文，欢迎感兴趣的同学参加。
```

Agent 会先生成未发布草稿，用户确认后才发布。也可以在 `/agent` 页面使用帖子工作台手动编辑标题、正文、类型和匿名状态。

### 3.5 当前帖子互动

在具体帖子页面使用：

```text
评论：今晚可以一起读第一章，我也可以整理笔记。
给这篇帖子点赞。
收藏当前帖子。
```

动作目标由当前页面资源编号确定，不能通过提示词把操作替换到用户无权访问的帖子。

查询个人内容：

```text
列出我发布的帖子。
列出我点赞过的帖子。
列出我收藏的帖子。
```

### 3.6 搭子与组队

```text
帮我找 AI 学习相关的组队。
申请加入这个组队。
在搭子群聊发送：我今晚八点可以参加讨论。
```

加入组队时：

- 联系方式必须由用户在确认弹窗中本人填写。
- 联系方式不会进入 LLM 对话上下文。
- 直接加入模式调用原直接加入流程。
- 审核模式提交申请说明和联系方式。
- 仍执行圈成员、组队状态、人数、候补、拉黑和重复申请检查。

### 3.7 匹配协助

在匹配/揭晓页面：

```text
总结一下本次匹配的共同点。
接受当前匹配。
拒绝这次匹配。
```

接受或拒绝属于不可随意撤销的选择，必须经过确认。Agent 只能操作当前登录用户自己的、状态为 `REVEALED` 且尚未选择的匹配。

### 3.8 通知

```text
查看我的未读通知。
将全部通知标为已读。
```

结果卡片也提供单条“标为已读”。所有已读状态变更都需要确认。

## 4. 页面感知范围

| 页面 | Agent 实际读取内容 |
|---|---|
| `/forum/:postId` | 当前帖子正文、互动状态和有限评论 |
| `/circles/:circleId` | 圈子详情、成员状态和公开属性 |
| 圈内茶话页面 | 圈子详情和最近 20 条授权消息 |
| `/circles/:circleId/teamups/:teamupId` | 组队详情；成员可额外读取最近群聊 |
| `/reveal`、匹配页面 | 当前用户的匹配状态、对方公开资料和自己的选择状态 |
| `/notifications` | 最近通知或未读通知 |

用户自行修改 `resourceId` 不能绕过权限，因为每个读取工具都会重新调用原服务的成员、可见性和资源归属检查。

## 5. 确认与安全机制

### 5.1 写操作流程

```text
用户自然语言
  → 确定性解析为结构化动作
  → 创建数据库动作记录
  → UI 展示目标和副作用
  → 用户确认
  → 签发五分钟有效的单次令牌
  → 原业务服务重新校验权限并执行
  → 保存执行结果或失败审计
```

### 5.2 持久化

Agent 草稿、确认挑战和执行审计保存在 `agent_action_records` 表中：

- 草稿默认 30 分钟过期。
- 确认令牌默认 5 分钟过期。
- 数据库只保存令牌的 SHA-256 摘要，不保存明文令牌。
- 令牌绑定用户、动作类型和资源。
- 令牌只能消费一次。
- 后端重启后，未过期的草稿和确认仍然有效。
- 执行成功和失败都会保留审计结果。

### 5.3 隐私边界

- 页面、聊天、匹配和通知内容只按当前用户权限读取。
- 已删除的聊天消息不会进入 Agent 上下文。
- 每次只读取有限数量的近期消息，避免无界上下文。
- 组队联系方式由用户在确认弹窗填写，不发送给模型。
- Agent 不读取联系人密钥、加密密钥、API Key 或服务器环境变量。
- 模型输出不能直接执行；只有服务端认可的结构化动作类型可以进入确认流程。

## 6. 当前仍不开放的操作

以下能力尚未开放给 Agent，仍需用户进入原页面完成：

- 自动填写或修改个人资料、问卷答案。
- 主动发送私信或好友申请。
- 创建、解散或退出圈子。
- 圈主审核、移除成员、拉黑、转让圈主。
- 创建、取消或管理组队，审核其他人的组队申请。
- 删除帖子、删除他人内容、举报和管理操作。
- 投递或撤销心动信笺。
- 查看无权访问的圈聊、组队群聊、私密帖子或联系方式。

这些操作涉及身份资料、隐私披露、破坏性变更或管理权限，需要独立风险设计，不能复用普通确认流程直接开放。

## 7. 本地验收建议

1. 从悬浮 Agent 发起检索，再展开 `/agent`，确认会话连续。
2. 在帖子页测试“评论：……”并取消，确认没有产生评论。
3. 再次执行并确认，检查评论出现。
4. 在圈聊页面要求总结最近讨论，确认引用真实聊天内容。
5. 使用非圈成员账号访问圈聊指令，预期返回权限错误。
6. 在组队页申请加入，确认必须手动填写联系方式。
7. 创建帖子草稿并签发确认，重启后端后再发布，确认仍可执行。
8. 重复使用同一确认令牌，预期返回 `403`。
