# 需求规格说明书 (论坛与治理模块) - V1.0

## 1. 引言
**1.1 目的**
[AI生成] 本文档详细描述了校园平台“论坛与治理”子系统的功能与非功能需求，为后端接口开发、数据库设计及测试提供基准。
**1.2 范围**
[AI生成] 本系统涵盖前端论坛的信息流展示、用户交互（发帖/回复/举报），以及后端的运营看板、内容风控与账号违规处理流程。不包含基础的注册登录与弱关系链管理。
**1.3 定义与缩写**
* [AI生成] 软删除（Soft Delete）：在数据库中仅修改记录的状态字段（如 `is_deleted = 1`），而不物理抹除数据，以便后续审计或恢复。
* [AI生成] 审计日志（Audit Log）：记录管理员在后台的所有操作行为，以备追溯。

## 2. 总体描述
**2.1 产品视角**
[AI生成] 作为整个校园平台的公共交流大盘和安全防线，本子系统需提供高可用性的信息流服务，并确保违规内容能被迅速隔离。
**2.2 用户特征**
* [AI生成] 普通学生：进行日常浏览、发帖求助、评论互动及行使监督权（举报）。
* [AI生成] 平台管理员：处理举报工单、监控平台运行数据、执行账号封禁与内容审查。

## 3. 功能需求
**3.1 论坛核心交互 (FR-01)**
* [AI生成] **FR-01-1:** 系统支持用户发布包含纯文本、图文混合的帖子，并可选择对应的板块标签（优先级：高）。
* [AI生成] **FR-01-2:** 系统支持主楼下方的盖楼式评论及楼中楼回复（优先级：高）。
* [AI生成] **FR-01-3:** 楼主拥有对其帖子下评论的折叠权限（优先级：中）。

**3.2 社区治理与风控 (FR-02)**
* [AI生成] **FR-02-1:** 用户可对违规的帖子或评论发起举报，选择违规类型并补充描述（优先级：高）。
* [AI生成] **FR-02-2:** 针对特定用户，系统提供“拉黑”功能，拉黑后信息流中不再呈现对方内容（优先级：高）。
* [AI生成] **FR-02-3:** 被系统或管理员处罚的用户，可通过专属通道提交申诉材料（优先级：低）。

**3.3 管理后台与运营 (FR-03)**
* [AI生成] **FR-03-1:** 管理后台需提供待处理举报的工单列表，支持“确认违规”或“驳回举报”操作（优先级：高）。
* [AI生成] **FR-03-2:** 管理员可对严重违规账号执行阶梯式封禁（如禁言 3 天、封禁 7 天、永久封停）（优先级：高）。
* [AI生成] **FR-03-3:** 所有后台的审核、封禁、解封操作，必须写入不可篡改的审计日志表（优先级：高）。

## 4. 非功能需求
* [AI生成] **4.1 并发与性能:** 信息流接口（Feed 流）的查询响应时间需在 500ms 以内，支持高并发读取。
* [AI生成] **4.2 数据一致性:** 帖子被软删除后，其关联的评论和点赞数据需在逻辑上级联失效，不再对前端暴露。

# 需求规格说明书 (论坛与治理模块) - V1.1

## 1. 引言
**1.1 目的**
[人工补充] 本文档旨在为“校园社交与互助平台”的论坛及治理子系统提供详细的功能定义。不同于通用的社交软件，本系统重点解决校园环境下“熟人社交压力”与“社区氛围治理”之间的矛盾，为后续的数据库设计和后端开发提供直接依据。

**1.2 范围**
[AI生成+人工修改] 系统主要覆盖：
1. 论坛交互：支持富文本发帖、多级评论及楼中楼互动。
2. 隐私保护：核心的“前台匿名/马甲”切换机制。
3. 社区治理：包含举报、申诉、黑名单以及基于“阳光值”的信用体系。
4. 管理后台：供学生管理员使用的审核工作台、审计日志及运营看板。

**1.3 定义与缩写**
* [人工补充] **马甲 (Vest)：** 用户在发帖时选择的临时匿名身份，系统前台不显示真实 ID。
* [人工补充] **阳光值 (Sunlight Value)：** 衡量用户社区行为质量的量化指标，直接关联发帖频率和板块权限。
* [AI生成] **软删除 (Soft Delete)：** 逻辑删除，数据保留在后台用于合规审计，但前台不可见。

## 2. 总体描述
**2.1 产品视角**
[人工补充] 论坛模块是整个平台的“流量入口”和“信息集散地”。它不仅要承载求助信息，更要通过良好的治理机制（如举报反馈闭环）来避免传统“校内表白墙”容易出现的戾气和造谣问题。

**2.2 用户特征**
* [人工补充] **普通学生：** 深度吃瓜群众，对隐私敏感，期望在安全的前提下进行选课避雷、吐槽或寻求技术帮助。
* [人工补充] **学生版主/仲裁委：** 负责日常违规内容清理。他们需要透明的操作标准，以防被指责“滥用权限”。

## 3. 功能需求

**3.1 论坛核心交互 (FR-01)**
* [AI生成+人工修改] **FR-01-1: 多媒体发帖。** 支持 Markdown/富文本编辑，支持最多 9 张图片上传。系统需自动对大图进行压缩处理。 (优先级: 高)
* [人工补充] **FR-01-2: 灵活标签系统。** 发帖时必须选择一个大板块（如“学习交流”、“生活槽点”），并允许自定义 2-3 个 Tag。 (优先级: 高)
* [人工补充] **FR-01-3: 双重匿名机制。** 系统提供“实名/匿名”一键切换。匿名状态下，系统随机分配临时代号（如：路人甲）。[依据问卷 Q5] (优先级: 最高)
* [AI生成+人工修改] **FR-01-4: 互动增强。** 支持点赞、踩、收藏功能。楼主有权折叠其帖子下方的无关评论。 (优先级: 中)

**3.2 治理与风控机制 (FR-02)**
* [AI生成+人工修改] **FR-02-1: 闭环举报系统。** 用户可对违规内容举报。系统承诺在 24 小时内处理，并**必须**通过站内信反馈处理结果（不论是否判定违规）。[依据问卷 Q7] (优先级: 高)
* [人工补充] **FR-02-2: 阳光值信用分。** 初始 100 分。违规扣分，活跃加分。分值低于 60 分限制发帖频率，低于 30 分自动执行 7 天禁言。 (优先级: 高)
* [人工补充] **FR-02-3: 社区拉黑功能。** 用户拉黑某人后，系统需在全站 Feed 流中屏蔽该用户的所有信息，且对方无法在自己的帖子下评论。 (优先级: 中)

**3.3 管理与运营看板 (FR-03)**
* [AI生成+人工修改] **FR-03-1: 审核工作台。** 提供待处理举报列表，支持查看帖子历史快照（防止用户在举报后修改内容逃避惩罚）。 (优先级: 高)
* [人工补充] **FR-03-2: 申诉处理通道。** 用户对处罚不满时可提交申诉，由人工版主进行二次复核。 (优先级: 低)
* [AI生成+人工修改] **FR-03-3: 审计日志。** 记录所有管理员的操作（谁删了贴、谁封了号），且该日志对所有管理员透明，防止内部人操作。 (优先级: 中)

## 4. 非功能需求
* [人工补充] **4.1 隐私保障 (安全性):** 数据库必须实现“前台匿名、后台实名”的数据隔离。任何前端接口不得暴露用户的真实 UID。 (优先级: 最高)
* [AI生成] **4.2 响应速度:** Feed 流首屏加载时间需控制在 1.5 秒内，确保流畅的吃瓜体验。
* [人工补充] **4.3 界面友好度:** 适配手机端展示，特别是代码块在移动端的横向滚动优化。
