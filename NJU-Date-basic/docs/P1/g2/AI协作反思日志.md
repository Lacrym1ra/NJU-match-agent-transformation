## 2. AI 助力分析（Q1）
本阶段 AI 最大的贡献是：
1. 可快速生成结构化模板与初稿，显著降低从0到1的文档搭建成本。
2. 能把我已明确的业务意图转写成更书面、规范的表达形式。
3. 问卷格式可直接整理为问卷星导入格式，避免手工逐题录入。
4. 能基于问卷与访谈结果快速提炼对应用户需求，减少逐条手工归纳工作。

估计节省时间：约 60%。

## 3. AI 误导分析（Q2）
发现的 AI 输出问题：
- 问题1：AI默认倾向 happy path，对异常流考虑不足。
	如何发现：在生成用例/流程时，扩展事件流与异常分支（备选流程）覆盖不完整。
	如何修正：在 Prompt 中显式要求覆盖异常场景，并指定异常类型（被拒绝、权限不足、网络中断等）。

- 问题2：约束不足时 AI 会过度发挥；约束过强且有缺漏时，AI又会机械执行并遗漏关键信息。
	如何发现：访谈记录整理时，虽然要求“保留真实性”，AI仍出现过度总结；只有明确“除合并同一人多段发言外不要大改”后，输出才符合预期。
	如何修正：要求必须“明确、直接、可检查”；提交前反复自查 Prompt，避免遗漏条件导致输出缺项。

- 问题3：AI对“必须包含”条款会执行得很严格，但通常不会主动补全你未写出的应有内容。
	如何发现：用例详细描述中我写了必须包含项但漏写“后置条件”，AI也未补充该部分。
	如何修正：在 Prompt 增加兜底句式，例如“若你认为还应补充内容，请补充并说明理由，但保持边界不变”。

- 问题4：不同 AI 在不同任务上的优势差异明显，输出风格与质量不一致。
	如何发现：同一任务分别用 Gemini 与 Claude 生成后，问卷质量与用例质量的优势模型不同。
	如何修正：按任务类型选择模型，必要时双模型并行生成后人工对比择优。

- 问题5：用户故事对轻度异常流有覆盖，但深层业务异常与系统级异常仍有缺口；部分验收标准缺少 Given 等前置定义。
	如何发现：人工审核发现边界值、容量限制、跨模块状态冲突场景覆盖不足。
	如何修正：将 AI 结果作为 Baseline，再人工补齐内容安全校验、极限值约束、跨模块异常（如拉黑+申请入圈）与缺失验收标准。

- 问题6：需求文档无法完全覆盖或准确还原访谈中的真实需求语义。
	如何发现：人工将 AI 产出与访谈原始记录逐项比对时发现偏差与遗漏。
	如何修正：以真实访谈和调研结论做二次校正，将人工证据回填到SRS并补齐缺失需求。

## 4. Prompt 改进计划（Q3）
本阶段使用的 Prompt 策略存在的问题：
1. 早期提示词在“边界约束”与“异常场景”上不够显式，导致输出偏向理想流程。
2. 局部任务中过度强调“必须包含”，但未给出“可补充项”指令，造成内容被动收缩。
3. 个别任务对“保留原文/避免过度总结”的约束表达不够刚性。

下阶段计划采用的改进措施：
1. 统一使用“目标-范围-排除项-输出格式-验收口径”五段式 Prompt 模板。
2. 所有分析/建模类任务强制加入“异常流检查清单”（权限、网络、频控、状态冲突）。
3. 对改写类任务加入刚性约束：可做的改动、禁止改动、保真级别与审阅标准。
4. 对关键文档采用“双模型生成+人工对比”的流程，按任务类型选择最优模型。
5. 在输出要求里补充“若发现缺失请主动补齐并标注”条款，降低机械遗漏风险。

## 5. 本阶段的核心工程判断
（记录一个 AI 无法替你做出的关键决策）
决策内容：将 AI 生成结果定位为“可快速迭代的基线文档”，而不是可直接提交的最终交付；关键需求、异常流覆盖与验收标准必须经过人工复核与补强。

为什么 AI 无法做这个决策：
1. AI缺乏对课程交付口径、团队分工边界与评审偏好的上下文责任。
2. AI难以从有限 Prompt 中完整还原真实访谈语义与隐性业务约束。
3. 是否“可提交”本质是工程质量与风险取舍判断，需要结合项目目标、证据链完整性与团队责任由人做最终决策。
