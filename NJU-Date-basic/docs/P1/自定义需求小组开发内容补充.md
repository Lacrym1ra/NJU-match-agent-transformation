# 自定义需求小组开发内容补充说明

> 项目：NJU-Match（校园社交组队与互助平台）
> 阶段：Phase 1 需求分析补充说明

## 一、补充说明目的

本项目属于自定义需求项目，不完全等同于课程样例中的标准题目。因此，除 Phase 0 / Phase 1 的标准文档交付外，还需要额外说明：

> 这个自定义项目在后续阶段**到底准备开发哪些内容**，以及这些开发内容如何在三组之间分工并形成完整系统。

本说明重点介绍后续的开发范围、模块边界和实施内容。

## 二、开发内容认定原则

对于自定义需求项目，本说明中的“开发内容”特指以下两类内容：

### 2.1 面向实现的功能开发内容

指项目后续要真正完成的系统能力，包括：

- 页面与交互流程；
- 后端接口与业务逻辑；
- 数据库结构与状态流转；
- 测试、联调、部署与演示支撑。

### 2.2 面向实现的详细方案内容

指那些已经达到“可直接指导开发”的设计与规划内容，包括：

- 模块拆分明确的功能方案；
- API 边界清晰的接口文档；
- 可用于分组协作的开发计划；
- 数据与权限模型明确的详细设计。

本说明**不把纯创意、灵感或头脑风暴当作开发内容**，只统计那些已经可以直接支持后续编码实现的内容。

## 三、项目整体开发内容

本项目围绕“校园社交组队与互助平台”展开，核心开发内容如下：

| 开发方向 | 计划开发内容 |
|---|---|
| 用户管理 | 注册登录、身份校验、个人资料、参与状态、通知偏好 |
| 推荐与匹配 | 问卷、匹配算法、揭晓机制、历史记录、双向确认 |
| 圈子与关系 | 圈子发现与加入、成员列表、名片、好友、联系方式解锁 |
| 内容与互动 | 论坛发帖、评论回复、活动组队、圈子接入论坛 |
| 治理与安全 | 举报、拉黑、审核、审计、信用分/阳光值 |
| 工程与运维 | 前后端工程结构、数据库设计、CI、部署与环境配置 |

从课程目标看，这些内容共同组成一个完整的平台，而不是单一页面或单一子功能。

## 四、按三组划分的开发内容

### 4.1 第一组：用户主线与互动建立组

第一组负责平台最核心的“主匹配链路”，开发内容主要包括：

#### 功能开发内容

- 用户注册、登录、身份认证与账户设置；
- 个人资料填写、编辑与参与状态切换；
- 问卷获取、填写、版本更新与答案管理；
- 匹配结果生成、揭晓、历史回看与结果反馈；
- 匿名心意表达、双向意向确认、通知提醒。

#### 对应的实施内容

- 登录页、建档页、问卷页、仪表盘、揭晓页、历史页等页面；
- 认证接口、用户接口、问卷接口、匹配接口、通知接口；
- 用户表、问卷答案表、匹配结果表、通知表、历史记录表；
- 针对认证、问卷、匹配、揭晓主链路的测试与联调。

### 4.2 第二组：圈子与关系链组

第二组负责平台中“弱关系建立与持续互动”的开发内容，主要包括：

#### 功能开发内容

- 圈子发现、加入、退出、成员展示与频道页；
- 用户名片、公开名片、好友名片与分级可见；
- 好友申请、同意/拒绝、关系链维护；
- 联系方式解锁申请、审批与可见控制；
- 圈内问卷、圈内推荐、活动组队与圈内互动；
- 圈子页进入论坛的入口衔接。

#### 对应的实施内容

- 圈子列表页、圈子详情页、成员页、名片页、好友页、联系方式解锁页；
- 圈子接口、名片接口、好友接口、隐私解锁接口、圈内推荐接口；
- 圈子表、成员表、名片表、好友关系表、解锁申请表；
- 针对圈子加入、好友申请、权限控制、组队互动的测试与联调。

### 4.3 第三组：论坛与治理组

第三组负责平台的“公共交流与治理闭环”，开发内容主要包括：

#### 功能开发内容

- 论坛板块、发帖、评论、回复与软删除；
- 举报、拉黑、处理反馈与前台治理入口；
- 管理后台、审核、公告、运营看板与审计日志；
- 信用分/阳光值机制及其权限联动；
- 圈子接入论坛，包括圈子专属帖流与圈子组队帖。

#### 对应的实施内容

- 论坛列表页、帖子详情页、评论区、举报处理页、管理后台页、运营看板页；
- 论坛接口、举报接口、拉黑接口、审核接口、统计接口；
- 帖子表、评论表、举报表、拉黑表、审计日志表、信用分相关数据结构；
- 针对内容发布、评论流转、举报审核、权限与异常场景的测试。

## 六、结论

对于“自定义需求小组需补齐开发内容”的要求，本项目的补充口径如下：

1. 我们不仅提交需求分析文档，还明确说明了后续要开发的系统模块；
2. 这些开发内容已经被拆分到三组，并形成清晰的功能边界；
3. 每组负责的内容都不仅包含页面，还包含接口、数据、测试与联调；
4. 相关 API 文档、模块计划和设计方案已经达到可直接指导开发的程度。

因此，这份补充说明的作用不是强调“哪些已经做完”，而是明确说明：

> 作为自定义需求项目，NJU-Match 在进入正式编码阶段前，已经具备了清晰、完整、可实施的开发内容定义。
