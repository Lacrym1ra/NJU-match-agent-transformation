## 一、文档说明

本文为 `docs/P1/` 目录下的统一版《三组需求分析汇总》，用于整合第一组、第二组、第三组三个小组在 Phase 1 阶段完成的需求分析成果，方便课程验收时以“一份总览 + 三组详细材料附件”的方式统一提交。

- 本文不替代各组原始交付物，而是作为需求分析阶段的统一入口与汇总页。

## 二、项目背景与自定义需求定位

本项目不是课程样例中“单一校园互助平台”的直接复刻，而是在课程要求基础上，扩展为一个三组共建的 **NJU-Match 校园社交组队与互助平台**。

项目希望同时覆盖以下几类校园需求：

1. 恋爱交友与低压力匹配；
2. 圈子、名片、好友和弱关系转强关系；
3. 论坛发帖、公共交流、活动组队与社区治理；
4. 举报、拉黑、审核、信用分、审计与后台运营。

因此，Phase 1 的需求分析目标不仅是完成标准作业要求，还要确保三组后续开发能够围绕同一个系统协同推进。

## 四、第一组需求分析汇总

### 4.1 模块定位

第一组负责平台最核心的主流程，即：

> 注册登录 -> 资料填写 -> 问卷提交 -> 每周匹配 -> 统一揭晓 -> 双向确认 / 反馈

### 4.2 调研结论摘要

第一组的调研结果表明：

- 学生对“低压力社交”和“按周节奏的匹配”有明确接受度；
- 用户对隐私安全、资料真实性和骚扰风险高度敏感；
- 用户不希望平台仅强调“匹配”，而是希望系统同时提供失败后的替代入口与温和反馈；
- 对纯恋爱导向存在犹豫，但对“先交朋友、再慢慢发展”的模式接受度更高。

### 4.3 核心需求摘要

第一组需要开发的核心需求包括：

- 邮箱认证与用户账户体系；
- Onboarding 建档与主问卷；
- 主匹配算法与状态机；
- 揭晓页、历史记录与双向选择；
- 匿名心意表达与意向确认。

## 五、第二组需求分析汇总

### 5.1 模块定位

第二组负责平台的圈子与关系链主线，目标是把用户从一次性连接，引导到长期、可协作的关系中。

核心业务链路为：

> 发现圈子 -> 加入圈子 -> 识别同好 -> 浏览名片 -> 建立好友 -> 解锁联系方式 -> 发起组队/圈内互动

### 5.2 调研结论摘要

第二组的调研结果表明：

- 用户愿意通过兴趣圈子建立弱关系；
- 对名片分级可见、好友前后信息差异化展示有明确需求；
- 不愿直接公开联系方式，更偏好“先申请、后授权”的机制；
- 圈内推荐、活动组队和群组互动有助于关系持续发展。

### 5.3 核心需求摘要

第二组需要开发的核心需求包括：

- 圈子发现、创建、加入、退出和成员管理；
- 公开名片、好友名片与字段级权限控制；
- 好友申请、处理与关系链管理；
- 联系方式解锁申请、审批、撤销；
- 圈内专属问卷、同好推荐、活动组队与互动频道。

## 六、第三组需求分析汇总

### 6.1 模块定位

第三组负责平台的论坛与治理主线，目标是在公共交流能力之上，建立平台秩序与治理闭环。

核心业务链路为：

> 发帖 -> 评论/回复 -> 举报/拉黑 -> 管理员处理 -> 反馈通知 -> 信用分约束

### 6.2 调研结论摘要

第三组的调研结果表明：

- 用户希望论坛支持多板块、多标签和楼中楼评论；
- 对“前台匿名、后台实名”的隐私机制有强烈需求；
- 举报不能“石沉大海”，需要明确的处理反馈；
- 用户认可信用分/阳光值机制，但前提是规则透明、处罚合理。

### 6.3 核心需求摘要

第三组需要开发的核心需求包括：

- 论坛发帖、评论、标签、板块与软删除；
- 匿名马甲机制与真实身份保护；
- 举报、拉黑、审核与处理反馈；
- 管理后台、工单流转、审计日志；
- 阳光值/信用分与治理联动；
- 圈子接入论坛后的圈子帖与组队帖机制。

## 七、跨组统一需求结论

经过三组需求分析，可以得出以下统一结论：

1. 本项目不是单一恋爱匹配产品，也不是单一互助论坛，而是一个以校园社交为核心、兼具圈子关系链和社区治理能力的综合平台。
2. 第一组、第二组、第三组分别承担主匹配链路、关系沉淀链路和公共交流治理链路，三条主线共同构成完整系统。
3. 用户对平台的共同要求集中在：
   - 真实性与低骚扰；
   - 隐私边界清晰；
   - 平台反馈明确；
   - 功能之间存在自然流转，而不是割裂使用。
4. 自定义需求项目除标准需求分析材料外，还需要明确说明后续开发范围，因此应结合 [自定义需求小组开发内容补充说明](./%E8%87%AA%E5%AE%9A%E4%B9%89%E9%9C%80%E6%B1%82%E5%B0%8F%E7%BB%84%E5%BC%80%E5%8F%91%E5%86%85%E5%AE%B9%E8%A1%A5%E5%85%85.md) 一并验收。
