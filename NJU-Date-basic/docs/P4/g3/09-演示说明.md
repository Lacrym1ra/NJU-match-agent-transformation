## 1. 运行方式：G3 演示环境一键启动

```bash
# 清理旧数据 + 完整启动（PostgreSQL + 后端自动迁移和种子 + Nginx 前端）
docker compose -f docker-compose.g3-demo.yml down -v
docker compose -f docker-compose.g3-demo.yml up -d --build


# 执行完上述两条后，直接进入下方前端访问地址即可开始使用，刚启动成功需要一些时间连接数据库，如果主页人数显示0请刷新几次。

# 前端访问地址：http://localhost:8080
# 后端 API：http://localhost:8080/api/v1
```

> 启动时自动执行 `seedForumDemo.ts`，该脚本内置数据库迁移和演示数据导入，无需手动执行迁移。使用独立 Compose 服务和独立 volume，不影响其他环境。容器名由 Docker Compose 自动生成，避免本机残留同名容器导致启动冲突。

> 如需重建演示数据：
> ```bash
> docker compose -f docker-compose.g3-demo.yml down -v    # 清数据库
> docker compose -f docker-compose.g3-demo.yml up -d      # 重新启动
> ```

### 3.14 私信隐私与防打扰

- **操作步骤：** 
  1. 使用"林溪"登录，进入仪表盘
  2. 点击底部「档案设置」Tab
  3. 在「私信与防打扰」区域，查看四种隐私等级：
     - **所有人**：任何用户都可以先发私信
     - **我关注的人**：仅已关注的用户可以发起私信
     - **互相关注的人**：仅双向关注的用户可以发起私信
     - **所有人都不可以**：完全关闭陌生私信
  4. 切换隐私等级（实时生效，无需保存按钮）
  5. 切换到"所有人都不可以"
  6. 换用"沐阳"账号登录，尝试给"林溪"发私信 → 提示"由于对方的隐私设置，暂时无法发送私信"

- **预期结果：**
  - 隐私等级切换即时生效，页面提示"私信与防打扰设置已实时生效"
  - 非互关对话有 **3 条消息限制**，超出后提示需等对方回复

### 3.15 拉黑与举报用户

- **操作步骤：** 
  1. 使用"林溪"登录，进入任意他人主页（如沐阳 `/user/:userId`）
  2. 点击右上角「···」菜单按钮
  3. 点击「拉黑」→ 确认操作
  4. 页面提示"已拉黑该用户"，按钮变更为「解除拉黑」
  5. 打开私信沐阳界面 → 显示"你已拉黑对方，将不再接收私信"
  6. 使用"沐阳"登录，打开私信林溪界面 → 显示"由于对方屏蔽设置，无法发送私信"
  7. 使用"林溪"登录，再次点击「···」→「解除拉黑」→ 恢复正常
  8. 进入另一用户主页，点击「···」→「举报」
  9. 弹出举报弹窗，勾选举报原因（挑衅/骚扰/广告/其他），可选填补充说明
  10. 提交举报 → 提示"举报已提交，等待管理员审核"

- **预期结果：**
  - 拉黑后双方均无法互相私信，UI 立即反馈
  - 解除拉黑恢复私信资格
  - 举报弹窗支持多选原因 + 文字补充说明
  - 举报提交后生成审核工单，管理员可在 `/admin` 查看
  - 重复举报同一用户会被拦截（幂等保护）

## 4. 注意事项

- 演示前请确保已执行 `docker compose -f docker-compose.g3-demo.yml down -v` 清空旧 volume。
- 默认使用宿主机 8080 端口；如需临时切换，可使用 `FRONTEND_PORT=8081 docker compose -f docker-compose.g3-demo.yml up -d --build`。
- `seedForumDemo.ts` 内置迁移和清空逻辑，每次运行都会重建干净数据。
- 推荐排序依赖 `pg_trgm` 扩展（迁移脚本自动启用）。
- G3 演示环境使用 `Dockerfile.demo` 构建，与生产 `Dockerfile` 独立。
- 所有帖子为全站论坛帖子，不关联任何圈子。
