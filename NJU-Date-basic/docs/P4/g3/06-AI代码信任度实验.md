# "AI 代码信任度实验"报告

> **实验日期：** 2026-05-10 
> **实验对象：** 论坛帖子列表 API（`GET /api/v1/forum/posts`）完整前后端链路  
> **AI 工具：** Claude Code (Claude Opus 4.x)

---

## 一、实验目的

评估 AI 生成的代码能否直接用于生产环境，以及人工审查能发现哪些 AI 忽略的问题。选择"论坛帖子列表"这一中等规模功能点（涉及后端查询、分页、筛选、排序、匿名mask、权限过滤，以及前端列表渲染），观察 AI 代码的可信度。

---

## 二、步骤一：AI 直接生成

### 2.1 Prompt 摘要

```
请实现论坛帖子列表 API 和前端页面。

后端要求：
- GET /api/v1/forum/posts
- 支持分页（page/limit）、类型筛选（type）、排序（sort=latest|hot）、关键词搜索（keyword）
- 帖子类型：general|squad|help|trade|activity
- 软删除过滤（deleted_at IS NULL）
- 热度排序公式：hot_score = (like*3 + favorite*4 + comment*5) / (1 + hours_since_creation/24)
- 匿名帖作者信息对非作者用户mask
- 私密帖仅作者可见，不出现于列表
- 置顶帖优先展示

前端要求：
- React + TypeScript
- 帖子卡片列表，展示标题、作者、类型标签、点赞数、评论数、时间
- 类型筛选Tab，排序切换按钮，搜索框
- 分页加载（滚动加载更多或分页按钮）
- 空状态、加载状态、错误状态处理
```

### 2.2 AI 生成结果摘要

AI 一次性生成了约 350 行后端服务代码（`listPosts` 函数）和约 250 行前端页面代码。主要结构：
- 后端：SQL 查询构建、分页计算、JOIN 用户表获取作者信息、LEFT JOIN 点赞/收藏表获取当前用户状态
- 前端：useState 管理筛选状态、useEffect 触发数据请求、motion 动画列表

## 三、步骤二：人工检查与修复

### 3.1 检查维度与发现

**维度 1：符合 P3 详细设计？**

| 检查项 | AI 实现 | 是否合规 |
|--------|---------|---------|
| 帖子类型枚举 | `general\|squad\|help\|trade\|activity` | ✅ |
| 软删除过滤 | `deleted_at IS NULL` | ✅ |
| 热度排序 | 使用 hot_score 公式 | ⚠️ 公式缺 viewCount 因子 |
| 置顶优先 | `ORDER BY is_pinned DESC, ...` | ✅ |
| 匿名mask | 非作者时替换作者信息 | ⚠️ 未处理 `isOwn` 判断 |
| 私密帖过滤 | 仅作者可见 | ✅ |
| 参数校验 | page/limit 边界 | ⚠️ 缺少 max(1) 保护 |

**维度 2：是否处理了常见异常和边界情况？**

发现以下问题：

| # | 问题 | 严重程度 | 说明 |
|---|------|---------|------|
| 1 | `limit` 无上限保护 | 中 | 用户可传 `limit=99999` 导致性能问题 |
| 2 | `page` 无下限保护 | 低 | 传入 `page=-1` 会导致 offset 为负 |
| 3 | `keyword` 未做长度限制和输入清洗 | 中 | 可传入超长字符串轰炸数据库 |
| 4 | 热度公式缺少 `view_count` 权重 | 低 | 与设计文档不完全一致 |
| 5 | 匿名帖 `isAnonymous` 字段布尔返回不一致 | 中 | 对作者返回 false，对其他用户返回 true，但前端判断逻辑含糊 |
| 6 | 类型筛选无效值时直接抛500错误 | 高 | 应返回 400 VALIDATION_ERROR 而不是让整个请求崩溃 |

**维度 3：是否存在明显 Bug 或不合理逻辑？**

| # | 问题 | 说明 |
|---|------|------|
| 1 | 热榜排序时未排除私密帖 | 私密帖会泄露到排序视图 |
| 2 | `authorScope='liked'` 时先查 liked post IDs 再 IN 查询，N+1 风险 | liked 数据量大时性能差 |
| 3 | 前端搜索使用受控组件但未做 debounce | 每输入一个字符就触发一次请求 |

### 3.2 修复记录

| 修复项 | 修改内容 | 修改文件 | 修改行数 |
|--------|---------|---------|---------|
| limit 上限 | `Math.min(50, Math.max(1, parseInt(...)))` | `forum.ts` | ~5行 |
| page 下限 | `Math.max(1, parseInt(...))` | `forum.ts` | ~2行 |
| keyword 清洗 | `split(/\s+/).filter(Boolean).slice(0, 6)` | `forumService.ts` | ~6行 |
| 热度公式 | 加入 `viewCount * 0.2` 及 `/86400` 修正 | `forumService.ts` | ~3行 |
| 无效类型处理 | `forumPostType.safeParse()` + 400 响应 | `forum.ts` | ~10行 |
| 热榜私密帖 | 增加 `visibility = 'public'` 条件 | `forumService.ts` | ~1行 |
| 前端 debounce | 使用 `setTimeout` 300ms debounce | `Forum.tsx` | ~8行 |

## 五、实验结论

1. **AI 生成的代码不能直接用。** 虽然代码结构合理、命名规范，但在边界条件、安全防护、错误处理等方面存在明显短板。
2. **AI 擅长"正常路径"的代码生成。** 分页、排序、JOIN 查询这些常规操作 AI 完成度很高。
3. **AI 不擅长的方面：**
   - 安全防护（参数校验、输入清洗、越权判断）
   - 业务规则边界（私密帖在所有查询路径中都要过滤）
   - 性能防护（limit 无上限、无 debounce）
   - 错误分类（不应把所有异常都抛 500）
4. **人工审查的必要性：** 即使 AI 代码可通过编译，也需要对安全性、数据权限、输入边界做系统性审查。这次实验中 6 个问题中有 4 个属于安全/防护类，AI 明显不会主动考虑这些方面。
5. **建议的审查清单：** 对于 AI 生成的代码，应逐项检查：参数边界、权限校验、异常处理、隐私保护、性能瓶颈。
